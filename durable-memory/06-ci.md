# Five-platform CI and releases

CI follows lmnum and the completed lmspace/lmbio templates. Linux x64/arm64, macOS x64/arm64 and Windows x64 install lmscript @lmctl-ai/lmctl@0.2.420, fetch pinned MFEM, verify SDK bytes, build/test and package one binary. GITHUB_TOKEN and LMFLUID_TEST_NETWORK are supplied to build tests. .gitattributes preserves LF for byte-identical schemas and pin hashes on Windows.

The MFEM build subtree is cached by platform, deps.lock and CMake configuration; CMake/Ninja rebuilds files when dependencies change. Serial configuration has no external numerical/TPL requirements. Only a v* tag enables the release job, after all five build jobs succeed. It validates --version against the tag and publishes five binaries, LICENSE and THIRD_PARTY_NOTICES. Build jobs are read-only; only the release job gets contents write access.

The first Windows run compiled the serial MFEM library successfully, then exposed use of nonstandard M_PI in our test sources under strict C++17. Native scientific oracles now use an explicit portable pi constant; this is not a MFEM limitation and does not justify the reduced fallback.

## v0.2.1 Linux dynamic glibc rollout (Rule 14)

Starting in v0.2.1, Linux CI jobs run on `ubuntu-22.04` and `ubuntu-22.04-arm` (minimum dynamic glibc >= 2.35) and link with `-static-libstdc++ -static-libgcc` while dynamically linking the system glibc and statically linking MFEM. `test.sh` enforces the `readelf -d` NEEDED allowlist (`libc.so.6`, `libm.so.6`, `libpthread.so.0`, `libdl.so.2`, `librt.so.1`, `ld-linux*`) on Linux.
